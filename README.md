# Пары

Fullstack-трекер лабораторных работ на Next.js App Router, React, PostgreSQL и Drizzle ORM. Интерфейс на русском языке, адаптирован для компьютеров, планшетов и телефонов.

## Возможности

- Расписание по субботам: по умолчанию 10:00–17:30, 30 слотов по 15 минут, сетка и список.
- Студент: материалы, прогресс, история каждой ЛР, PDF-отчёты, бронирование, отмена и атомарный перенос.
- Преподаватель: подтверждение, доработка с сохранением слота, отклонение, ручная неявка, оценивание.
- Администратор: создание курсов, создание и редактирование ЛР, создание бригад и генерация учётных данных, рабочие часы курса.
- Первый вход новой бригады: ФИО и контакты всех участников, согласие на ПДн с фиксацией времени и IP.
- Пароли: salted scrypt. Сессии: случайные токены, хеши токенов в PostgreSQL, HttpOnly cookies. В production используются Secure / SameSite=None / Partitioned для безопасной работы встроенного предпросмотра; в разработке — SameSite=Lax. Все изменяющие запросы проверяют Origin на сервере.
- Файлы: только PDF с проверкой сигнатуры, до 10 МиБ; каждая версия хранится в PostgreSQL и отдаётся через авторизованный API.
- Уведомления внутри приложения и полный журнал действий. Внешняя отправка email/Telegram не подключена.

## Принятые решения по ТЗ v3

1. Перезапись атомарная: отмена старого и создание нового бронирования в одной транзакции.
2. «Не явился» отмечается преподавателем вручную в субботу, после истечения 15 минут с начала подтверждённого слота. Работа автоматически возвращается в работу.
3. Максимум две активные брони на бригаду во всех курсах. Активные статусы: pending, confirmed, revision. Проверка на сервере под транзакционной advisory-блокировкой; занятость дополнительно защищена частичным уникальным индексом.
4. Разрешены две записи на одну ЛР, в том числе соседние слоты.
5. Запись, отмена и перенос доступны не менее чем за 24 часа. Причина отмены или переноса — минимум 10 символов.
6. Баллы — свободное конечное числовое значение: целые, дробные, ноль и отрицательные. Для выполненной защиты оценка обязательна. Завершение консультации не завершает лабораторную.
7. Срок сдачи информационный. Новая версия отчёта отправляет работу повторно на проверку; предыдущие версии не удаляются.

## Запуск

Проект использует `DATABASE_URL` из `.env`. Зависимости устанавливаются через npm.

- `npx drizzle-kit push` — применить схему к доступной PostgreSQL.
- `npm run dev` — разработка.
- `npx next typegen` — генерация типов маршрутов.
- `npm exec tsc -- --noEmit --pretty false` — проверка TypeScript.
- `npm run build` — production-сборка.

Демонстрационные данные создаются автоматически и транзакционно при первом обращении. Начальный экран — кабинет бригады №12. Меню профиля в правом верхнем углу позволяет открыть демонстрационный кабинет студента, преподавателя или администратора.

**Демонстрационная среда:** переключение демонстрационных ролей открыто специально для проверки приложения. Не используйте общие демо-кабинеты для настоящих персональных данных. Для публичного production-развёртывания необходимы отключение открытого demo-входа и выдача отдельных учётных записей преподавателям и администраторам. Созданные администратором бригады уже входят по собственным сгенерированным логину и паролю; пароль отображается только при создании.

## Проверки

`scripts/verify.ts` создаёт изолированные тестовые данные, проверяет API и интерфейс через Playwright, а затем удаляет временные данные через Drizzle.

- `npx playwright install --with-deps chromium` — подготовить браузер.
- `npx tsx scripts/verify.ts` — проверить dev-сервер на localhost:3000.
- `TEST_BASE_URL=https://your-preview-host npx tsx scripts/verify.ts` — проверить production по HTTPS (требуется для Secure-cookie).

Проверяются конкурирующие бронирования и лимит 2, коллизии одного слота, атомарный перенос и откат, правило 24 часов, авторизация, ПДн, PDF-сигнатура и размер, доступ к чужим файлам, версии v1/v2, доработка, балл 8.5, ручная неявка, действия администратора, навигация и отсутствие горизонтального переполнения на ширинах 390–1440 px.

Положительный сценарий неявки использует временную запись с прошедшим временем только в субботу. В остальные дни проверяется отказ при недопустимом времени. Реальная серверная валидация не отключается.

## Структура

- `src/db/schema.ts` — таблицы и индексы.
- `src/lib/server.ts` — сессии, безопасные проекции данных, начальные данные.
- `src/lib/actions.ts` — транзакционные правила предметной области.
- `src/app/api/` — авторизация, рабочее пространство, файлы, healthcheck.
- `src/components/` — рабочее пространство и диалоги.
- `public/fonts/` — локальные кириллические шрифты Manrope; внешних шрифтовых запросов нет.
